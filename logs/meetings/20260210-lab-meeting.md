## 2. 리소스별 에너지 귀인 모델 재확인

### CPU: 사용 기준 (이용률 비례)
- idle 차감 후 **이용률 비율**로 분배
- 동시 실행 시 각 워크로드의 CPU 이용률 필요 (cgroup으로 분리 가능)

### GPU: 할당 + 사용 혼합
- **코어**: 사용 기준 (이용률 비례)
- **GPU 메모리**: 할당 기준 (상수)
- GPU 2장이면 각각 할당, 1장이면 프로세스별 nvidia-smi로 이용률 분리 가능

### Memory: 할당 기준 (상수)
- cgroup으로 할당한 양에 비례하여 책임
- 예: 32GB 시스템에서 4GB 할당 → 전체 메모리 에너지의 1/8만 책임
- R/W에 의한 에너지 변화는 무시 가능 (리프레시가 대부분)

### Storage: 사용 기준 (IO량 비례)
- idle 시 에너지 ~0 (non-volatile)
- **fio로 단위 IO당 에너지 측정** → 실제 워크로드 IO량에 곱하여 책임 분배
- SSD이므로 **sequential read/write만** 측정하면 됨 (random은 생략 가능)
- 데이터시트 값 대신 **실측값 사용** (데이터시트는 부정확할 수 있음)

### Others
- 기본적으로 **상수**로 가정
- 워크로드가 늘어나면 Others도 증가하는 경우 → 모델을 수정하여 설명 가능

## 3. GPU 2장 문제

### 현재 상태
- Alienware에 GPU(RTX 3060) 2장 장착되어 있으나, **1장만 nvidia-smi에 감지됨**
- 나머지 1장은 vfio 설정으로 호스트에서 언로드된 상태
- **숨겨진 GPU가 기본 전력을 소모** → Others가 크게 나온 원인 중 하나

### 조치
- 조경훈 교수님: "두 개 다 활성화시키거나 아예 하나를 물리적으로 빼거나"
- 정화 씨에게 vfio 설정 확인 요청
- GPU 1장으로도 프로세스별 nvidia-smi로 이용률 분리 가능

## 4. DRAM/RAPL 관련

### RAPL DRAM 측정값이 너무 작음 (~2% 미만)
- 조경훈 교수님: "d램이 10-20%는 될 것 같은데 1-2%는 너무 작다. Others에 포함되어 있는 게 아닌가"
- 강 교수님: "d램 에너지가 작으면 작은 이유를 적당히 적으면 된다. 핵심이 아니다"

## 5. fio Storage 실험 피드백 (핵심 지적)

### 우림이 제시한 것
- fio(seq_read/write/rand_read/write) 실행 시 delta 값 ~46-47W를 "IO subsystem 전력"으로 제시
- SSD 데이터시트 스펙(3.2W)과 크게 차이남

### 교수님들의 지적

1. **delta 값에 CPU 전력이 대부분 포함됨**
   - 조경훈 교수님: "RAPL에서 부하 없을 때 10W이고, 스토리지 부하 주니까 20W이면, dCPU=10W가 포함된 것"
   - 강 교수님: "RAPL에서 잰 거면 거의 CPU 에너지. IO subsystem이라고 쓴 것은 사실 CPU도 포함돼 있다"

2. **fio의 목적은 "단위 IO당 스토리지 에너지 기본값"을 구하는 것**
   > "fio를 해서 스토리지 에너지의 기본 값을 알아내고, 각 워크로드의 read/write량을 잰 다음 곱하는 것" - 강 교수님

   - Storage_power = Wall(fio) - Wall(idle) - dCPU(RAPL) - dGPU
   - Storage_rate = Storage_power / Throughput (W per MB/s)
   - 실제 워크로드의 Storage_energy = Storage_rate × actual_IO_amount

3. **PCIe 컨트롤러 오버헤드도 존재**
   - 조경훈 교수님: "PCI 컨트롤러 자체에 걸리는 부하 전력도 있다. 보드 자체에 쓰이는 것. 그럼에도 너무 많다"

### 추가 필요한 것
- 이전 워크로드 실험에서 **storage read/write량이 기록되지 않았음** → 다시 측정 필요
- fio에서 구한 rate를 적용하려면 **각 워크로드의 IO량**이 있어야 함

## 7. Others가 크게 나오는 문제

### 현상
- Wall - CPU - GPU를 빼면 Others가 전체의 상당 부분 (40~60%)
- 조경훈 교수님 장비에서는 Others가 그리 크지 않았음

### 원인 분석
- GPU 2장 중 1장이 idle 전력 소모 중 (미측정)
- AC→DC 변환 손실 ~20% (PSU 효율)
- 쿨링팬, 기타 보드 전력
- 시스템 데몬 (끄면 줄어들 수 있음)

### 대응 방침
- Others를 상수로 놓고 진행, 결과가 일관성이 없으면 그때 모델 수정
- "워크로드가 늘어나면 Others도 늘려야 될 요소가 있나 보고 모델을 세워서 일관성 있는 결과가 되면 논문에 제시" - 강 교수님
